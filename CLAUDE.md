# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status: v1 shipped and installed

**Everything below describes real, tested code** (466 tests, 1 skip). The app is installed at `/Applications/Notable.app` and under daily use. The build plan that got here is `PLAN.md` — all phases including Phase 8 (dictation quality) are implemented.

Runtime health (measured 2026-07-12, Release build): idle CPU 0.0 %, RSS ~120 MB (ASR models warm-loaded at launch — deliberate), leaks 14 KB of framework XPC-cache noise.

## Scope: personal tool, not a product

Notable is built for a single user, running on their own machine. This is load-bearing: it resolves distribution (locally built, Developer ID signed, no sandbox), allows a locally installed CLI to act as a summarization provider, and forbids multi-user plumbing. If productization ever happens, revisit this section first.

## What Notable is

A local-first transcription app for macOS. Two modes share one core:

1. **Dictation** — hold a global hotkey (or tap for hands-free lock), speak, release; polished text is pasted into the focused field. Measured warm latency: 5 s audio → ~119 ms, 60 s → ~397 ms whole-clip; long dictations use incremental decoding so only the tail is left at release.
2. **Meeting transcription** — mic + system audio (CoreAudio process tap), auto-detected (Zoom/Teams/FaceTime/Webex/Slack + browser Meet/Zoom/Teams) or manual, diarized, attributed to the calendar event, summarized into Markdown.

Audio never leaves the device — architectural, not a toggle. Everything that leaves is text. **Dictation text leaves only on an explicit, per-invocation request**: the automatic polish stays rule-based and offline, and the LLM pass runs only when the user asks for it by hotkey or menu — and then only through a CLI provider, never through the API key. Note a CLI is *not* local: `claude -p` is a locally started process that ships text to a provider. Meeting transcript text may reach either provider (summarization, speaker naming, chat). See `specs/` (03 is offline-only; 04 — voice editing of arbitrary selected text — stays deferred).

## Architecture map

`project.yml` is the source of truth (xcodegen); `Notable.xcodeproj` and `Generated/` are gitignored. `AppContainer` (in `NotableApp.swift`) is the composition root; `AppDelegate` boots dictation, wires the meeting detector, and runs spool crash-recovery.

- `Sources/Notable/Dictation/` — the latency-critical path:
  - `HotkeyMonitor` — **two** CGEventTaps by design: an always-on *listen-only* flags tap (never in the synchronous key path) and an *active* Esc tap that exists only while recording. Never put an active tap on keyDown permanently.
  - `PTTStateMachine` (pure) — hold = push-to-talk, short tap = hands-free lock, next tap stops.
  - `AudioRecorder` → `Support/PCMDownsampler` (16 kHz mono; RAM for dictation, disk spool for meetings; RMS level).
  - `ParakeetTranscriber` (FluidAudio Parakeet TDT v3, multilingual, default) and `EnglishStreamingTranscriber` (Parakeet Unified, English-only true streaming) — selectable in Settings.
  - `IncrementalDictation` — long-clip decoding with carried `TdtDecoderState`, cut at silence seams; strictly best-effort with whole-clip fallback.
  - `TextPolisher` (pure) — filler removal (language-aware: "um"/"er" are German words, English fillers only on detected-English text), ITN (English-only, and the native lib is not bundled by SPM → currently pass-through), smart-replace expansions, personal dictionary, tidy. **`tidy` collapses horizontal whitespace only**: line breaks survive, because they can only have come from a `SmartReplace` expansion and a multi-line building block flattened to one line is not one.
  - `SmartReplace` (pure, issue #4) — spoken shorthands expanding to arbitrary, possibly multi-line text. Kept **separate from `PersonalDictionary` and out of the fuzzy pass** on purpose: the dictionary is a *correction* (both sides are the same word, so near-misses are cheap), an expansion is not — a fuzzy hit there writes a paragraph where a similar-sounding word stood. Matching is a genuine **single pass** over the original text (one alternation regex, leftmost-longest), so an expansion is never rescanned and two rows cannot be made into a loop. Runs in verbatim mode too — a shorthand is an instruction, not a beautification.
  - `ParagraphFormatter` (pure, issue #1 Stufe 1) — puts structure back *after* `tidy`: paragraphs by sentence count and the breaks/lists the user actually spoke ("neue Zeile", "Stichpunkt", "erstens…"). A command only counts when it **starts an utterance**, because "Aufzählung" and "neue Zeile" are ordinary German words. Breaks the text already carried are marked as a distinct kind and their following word is **not** re-capitalized — otherwise an expansion's mail address on its own line comes back as "Max.mustermann@…".
  - `DictationEnhancer` / `EnhancementGuard` (pure) / `EnhancementSettings` (issue #1 Stufe 2) — the **only** path on which dictated text leaves the device, and only because *this* recording was started with the second hotkey (or the menu item was chosen). `DictationEnhancer.dictationProvider` is hard-wired to a CLI provider — never `AnthropicAPIProvider`, not even when that is the selected *meeting* provider; a test pins it. **The settings switch is the consent** (it replaces the spec's one-time dialog: a dialog and a setting say the same thing once, and only the setting can be revoked), and while it is off `EnhancementSettings.hotkey()` returns nil, so the second key is not even installed. `enhance` **never throws**: a guardrail rejection, an error and a timeout all paste the rule-polished original, because losing a dictation to a failed network call is the worst available trade. Every run is booked into `llm_usage` (`purpose = "dictation-enhance"`, `billed = 0`) *even when the answer was discarded* — the row counts how often text left the device, not what it cost.
  - `HotkeyRouting` (pure) — which of the two push-to-talk keys fired. Extracted from `HotkeyMonitor`'s CGEventTap callback because that cannot be tested and this is the part that goes wrong: a release must be matched to the key that started the recording, a second key during a recording is ignored, and one key configured for both roles means plain.
  - `SpokenLanguages` (Spec 11) — the languages the user actually dictates in, fed to `NLLanguageRecognizer` as **constraints**. Unconstrained it will call a short German sentence Danish, and the English filler list then eats "er" out of it; constrained, the answer can only be a language they actually speak. Sits in the core path (`polish` runs on every dictation), so it is tested rather than trusted. A profile without English never reports English — intended, not a side effect. With exactly one language, Whisper's `DecodingOptions` pins it instead of detecting.
  - `BootstrapPolicy` (pure) / the bootstrap slot in `DictationController` (Spec 10) — on a **cold** cache Whisper Tiny (~75 MB, already a full engine here) carries dictation while the chosen model downloads. Never mid-recording: a swap that comes due during a recording is deferred to after the paste, because the transcriber the audio was recorded for has to finish the job. The stand-in is released afterwards so the ~120 MB baseline does not permanently grow. Presence is only checked authoritatively for **Parakeet v3** (FluidAudio's own file check); the other two report "present", which switches the stand-in off for them — a fresh install always starts on v3, so it is the only engine a cold cache can strand. A failing stand-in just disappears; it must never become an extra failure mode. **The provisional state is always said out loud** (overlay, menu, onboarding): Tiny is markedly weaker, and unmarked output would read as Notable's normal quality.
  - `MediaInterrupter` (Spec 08 B) — pauses playback / mutes output for the duration of a dictation. Both switches default **off**: this reaches outside Notable. Only ever undoes its own doing — nothing playing means nothing resumed, and a volume the user changed mid-dictation outranks the restore. An unavailable CoreAudio snapshot means *do nothing*, since a guessed play/pause could just as easily start a podcast as stop one.
  - `DictationOverlayView` / `WaveformView` — the HUD itself. **While recording it shows only the waveform**: a small dark capsule floating in the 380 × 68 transparent panel, not a banner filling it. The waveform keeps the last 18 level samples and moves, because a bar chart that only fills left to right is a volume gauge — dictation wants the shape of the speech. Its gain is 8 with a 0.7 exponent, not the old meter's 12: above 0.083 RMS that saturated, which is fine for five lamps and useless for a wave. Text appears only where the waveform cannot speak — the live partial, the way out of hands-free mode (holding the key needs no exit hint, letting go *is* the exit), and every non-recording state.
  - `NotchGeometry` (pure, issue #3) / `NotchOverlayView` — where the HUD sits: around the notch, a pill under the menu bar, bottom-centre, or off. One panel spans the notch strip with a transparent middle (two panels would double the never-become-key surface), and placement follows the screen under the **mouse pointer** — `NSScreen.main` is the screen with the key window, and this panel is never key.
  - `Paster` — pasteboard swap + synthesized ⌘V (600 ms restore delay for slow Electron apps) or typing injection (20 UTF-16 units per CGEvent).
  - `DictationOverlay` — non-activating NSPanel; **must never become key** or the paste-into-focused-field mechanic breaks. No longer only a comment: `DictationOverlayTests` builds the panel in both styles and asserts `canBecomeKey == false`, that showing it does not take `NSApp.keyWindow`, and the rest of the configuration it rests on. Verified by mutation — flipping `.borderless` to `.titled` fails the test.
- `Sources/Notable/Meeting/` — `SystemAudioTap` (process tap via private aggregate device; needs the separate "System Audio Recording" TCC, not Screen Recording), `MeetingDetector`/`DetectionStateMachine`/`AudioProcessMonitor` (per-process CoreAudio flags: start = a known app **holds the microphone** (2 ticks), end = that process has no audio left (4 ticks ≈ 20 s). Match process bundle ids by **prefix** — Electron/Chromium audio runs in `…​.helper`; Safari's runs as `com.apple.WebKit.GPU`, listed explicitly. End counts output only for dedicated apps, never for browsers/Slack, which play audio all day. The old "app is running + global mic bit" heuristic survives only as a fallback when the process list is unavailable — it could never end a call for Teams or Slack, which never quit), `MeetingPipeline` (VAD-segmented mic track "Ich" + diarized system track "Sprecher n" → per-segment ASR → polish), `SpoolStore` (crash-safe raw-PCM spool, recovered on launch), `MeetingController`.
  - `LiveNotes` (pure) / `LiveNotesController` / `LiveNotesView` — notes typed **during** the call. The window floats above the call (NSWindow level, `.canJoinAllSpaces + .fullScreenAuxiliary`; SwiftUI's `windowLevel` is macOS 15+), its editor is an `NSTextView` (SwiftUI's `TextEditor` exposes no caret, and ⌘T must stamp the elapsed time *where you type*), and it may become key — the "never become key" rule protects `DictationOverlay`'s paste-into-the-focused-field mechanic, and here the notes field *is* that field, so the dictation hotkey types into it. The buffer mirrors into the spool (`notes.md`) debounced, so a crash or a deferred meeting still carries the notes. `stop()` consumes it into the **existing** `userNotes` path: verbatim `## Eigene Notizen` in the Inbox note, ground truth for the summarizer, context for the chat. That path was fully built but had no caller — `produceNote(userNotes:)` was never populated.
  - `NotesMarkdown` (pure) / `NotesRichText` (AppKit) — the editor is **WYSIWYG**: no `##` or `-` is ever visible, headings are simply bigger, bullets are real `•`, checkboxes tickable `☐`. The buffer stays **Markdown** and remains the source of truth, so the spool mirror, crash recovery and the verbatim hand-off to the summarizer are untouched; `NotesRichText` translates at the view boundary only. **Where the block kind lives matters:** for lists the visible marker *is* the truth (`•\t` ⇒ bullet), so editing or deleting it does the obvious thing; only headings, which have nothing visible to key off, carry a hidden `.notesBlock` attribute. Keeping that the sole hidden state is deliberate — hidden state that drifts out of sync with the text is how WYSIWYG editors start mangling documents. The round-trip must stay **total and idempotent** (`NotesMarkdownTests`), because a drift here silently rewrites notes the summarizer treats as fact. Caret offsets are UTF-16 throughout (what `NSTextView` reports) and `position`/`utf16Offset` are pinned as exact inverses, including across a marker the user cannot see.
  - `TrackSilence` (pure) — **a recorded track that carries no signal is the shape every capture regression has taken**: VPIO gating the input graph (2026-07) and a hardened-runtime build without the microphone entitlement (2026-08, denied by tccd with no prompt) both produced exactly 0.0 peak PCM for whole meetings while the app reported success. The second case ran unnoticed for two weeks, because the *remote* track kept working and the notes read fine. So silence is stated, not inferred: `MeetingController` polls the mic meter for the first 20 s and says so out loud during the call, and `produceNote` judges both raw tracks and puts the warning in the status line and the notification. It also **skips speaker naming when the mic was silent** — a one-sided transcript attests only the name spoken *at* the local user, so the resolver would confidently paste that name onto the remote speaker. `SpeakerNameResolver` refuses the local user's own name outright (`ownerNameTokens`): the local user is `"Ich"` by construction, so their name on a remote label is an inversion, never a near miss.
  - **Never diarize the raw system track.** It is mostly silence (it holds nothing while *I* speak), and the silence destroys the speaker embeddings: measured on identical audio, the holes alone collapse a British male and an American female into one speaker, while the VAD-compacted signal separates them cleanly. The pipeline compacts to speech, diarizes that, and maps the times back (`SpeechRegion`/`mapToOriginal`). `MeetingConversationTests` is the guard.
- `Sources/Notable/Storage/` — `RecordingStore` (SQLite WAL, actor; full-text LIKE search), `MarkdownProjector` (notes carry start time in the filename — collision fix), `NotesFolder`, `RetentionPolicy`/`RetentionPlanner`/`RetentionRunner`. **Cleanup clears text, never rows** (issue #2): `UsageMetrics` reads only `recordings`, so deleting a row would retroactively rewrite how much was ever dictated — a different and much worse thing than freeing disk space. `segments.text` is emptied, `word_count` stays, and `usageRows` returns identical numbers before and after (`RetentionStoreTests`). Raw audio in `spool-archive/` is bounded on **two** axes (age *and* a total budget): a few weeks of use is enough to accumulate gigabytes, and a single session where a recording never ended can be larger than everything else combined — an age rule alone would never reach that one. `spool/` and the user's Markdown notes folder are untouchable, `spool-failed/` gets a longer grace period, and automatic cleanup stays **off until switched on**, because deleting someone's meeting audio unasked on the first launch after an update is not a default. The `llm_usage` table is **append-only and has no foreign key**: a meeting is summarized *before* its recording row is written (summary, subtitle and auto-title must land together), and a retried summary adds a row rather than replacing one, so the totals say what was actually spent.
- `Sources/Notable/Summarization/` — provider protocol, `SummarizationProviderID` (a domain rule, not UI: `cliProviders` is what the dictation path is allowed to reach), `CLIProcessRunner` (one shutdown sequence for every CLI — the grandchild processes that inherit the pipe, the CLI that ignores SIGTERM, the continuation that must resume exactly once; each lesson learned once), `AgentCLIProvider` for **Gemini CLI and Codex CLI** (described, not reimplemented: binary, arguments, candidate answer keys). Its parser is deliberately forgiving — JSON if it parses and carries a known text field, plain stdout otherwise — because these tools reshape their output between releases; JSON in an *unknown* shape throws rather than guessing which key is the answer. **Their invocations are documented, not verified**: only the Claude CLI was installed on the build machine, so the arguments are overridable per tool (`cliArguments.<id>`) and Settings has a "Verbindung testen" button. Plus `AnthropicAPIProvider` (`claude-sonnet-5`; **no sampling params — Sonnet 5 rejects them with 400**; check `stop_reason`) + `ClaudeCodeCLIProvider` (`claude -p --output-format json`, defensive parser). No silent fallback between providers; failed summaries are retryable from the menu. Both `summarize` and `complete` return their token spend (`SummarizationUsage`, `Completion`), which `UsageRecorder` books into `llm_usage` for all three purposes — summary, chat, speaker naming. **`billed` is the load-bearing field:** the API is metered per call, so its cost is real; a CLI backed by a flat-rate plan charges nothing per call and its reported `total_cost_usd` is only what the call *would* have cost. The two are never summed, all the way to the label. API prices are hard-coded per million tokens and **must be updated alongside `model`** — the API returns no price.
- `Sources/Notable/Stats/` — `UsageMetrics` (pure: buckets, savings, LLM spend, the issue-#5 detail analyses, and the shared number/duration/currency formatting), `StatsView` + `Stats/Cards/` (window; the "KI-Tokens" tile appears only once something has been summarized, the detail cards live in a collapsed "Details" section and are computed in `recompute` from rows already in memory — no extra SQLite round-trip), `UsageSummary` (the one-line "Heute: … Wörter · … gespart" row in the menu-bar dropdown). A `.menu`-style `MenuBarExtra` is built from `NSMenuItem`s and has no usable `onAppear`, so the line is **pushed**: refreshed at launch and after every dictation/meeting save, same as `DictationHistory`.
  **Measurement columns are nullable and never backfilled** (`engine`, `latency_ms`, `source_app`, `enhanced`): six weeks of existing rows never had them, so every analysis shows "Unbekannt" as its own row rather than folding it into the current engine — a guessed measurement in a statistics window is worse than a gap. Latency is reported as **median and p95, never the mean** (one cold model load shifts a mean by seconds) and stays `nil` below 10 samples. `source_app` never leaves SQLite; it is resolved to a name and icon at display time, and both the recording and the stored column can be switched off.
- `Calendar/`, `Permissions/`, `Search/` — EventKit read-only matching, live TCC status with deep links, local search window (⌘F from menu).

## Commands

**Build to a derived-data path outside the repo.** When the repo sits in a synced folder (iCloud Drive, Dropbox), the file provider decorates the build product with extended attributes and `codesign` then fails with `resource fork, Finder information, or similar detritus not allowed` — a build failure that looks nothing like its cause. `DD=$TMPDIR/notable` below; `scripts/install.sh` and `scripts/release.sh` do the same thing for the same reason.

```sh
DD="$TMPDIR/notable"
xcodegen generate                                    # after editing project.yml (also: new test files need explicit paths in the NotableTests sources list)
xcodebuild -project Notable.xcodeproj -scheme Notable -configuration Debug -derivedDataPath "$DD" build
open "$DD/Build/Products/Debug/Notable.app"
# Tests need the app module in the SAME derived data — build first, then:
xcodebuild -project Notable.xcodeproj -scheme Notable -configuration Debug -derivedDataPath "$DD" test
# single test:
xcodebuild ... test -only-testing:NotableTests/MarkdownProjectorTests/testFileNameIsFilesystemSafe
# install (Release) — TCC permissions stick to the bundle path, so grant them on /Applications:
scripts/install.sh
```

Signing needs `Signing/Local.xcconfig` (gitignored): copy `Signing/Local.xcconfig.example` and put your Apple Team ID in it. Without it the build stops at `Signing for "Notable" requires selecting either a development team or a provisioning profile`.

Test-suite notes: `ParakeetTranscriberTests`, `MeetingPipelineE2ETests`, `EnglishStreamingTests`, and `LatencyProbeTests` run real models (first run downloads GBs from HuggingFace, then cached; the full suite takes ~9 min). `ClaudeCodeCLIProviderTests` makes one real headless call through the logged-in Claude Code CLI (skipped if absent).

## Settled decisions

- **Scope**: personal tool, single user (above).
- **Dictation text leaves only on request** (**built**): the automatic polish after every dictation is offline/rule-based and always will be. An LLM pass over dictated text is allowed *only* when the user explicitly triggers it (dedicated second hotkey, or "Letztes Diktat verbessern" in the menu), and *only* through one of the **CLI providers** — Claude Code, Gemini CLI or Codex CLI — never via `AnthropicAPIProvider`. **The rule is about the per-call contract, not about a vendor:** a metered key turns every dictation into a line on a bill, a CLI does not; which vendor's servers see the text is the user's choice, and each one is named at the point of choosing. Anything unrecognised falls back to the Claude CLI rather than to whatever the meeting provider happens to be. The whole feature is off until a settings switch turns it on, and that switch **is** the consent. Each run is booked into `llm_usage` so the number of times dictation text left the device stays countable. LLM voice-command editing of arbitrary *selected* text (Spec 04) remains off the table.
- **Automatic cleanup stays opt-in**: the retention defaults (30 days / 20 GB) are ready but dormant behind `retentionEnabled`. Deleting gigabytes of meeting audio on the first launch after an update would be irreversible *and* unasked — the one combination worth a switch.
- **Distribution**: locally built, **Developer ID signed** + hardened runtime, installed to `/Applications` (TCC grants live there). It was ad-hoc (`"-"`), then Apple Development; Developer ID is what the notary service accepts, so `scripts/release.sh` can notarize and staple. Changing `CODE_SIGN_IDENTITY` again voids every TCC grant silently — the checkbox still looks ticked, nothing is logged, and the fn hotkey just stops. `project.yml` carries the symptom and the `tccutil reset` recipe next to the setting.
- **Deployment target**: macOS 14.4+ — CoreAudio process taps only, no ScreenCaptureKit fallback.
- **Models**: FluidAudio (SPM) supplies Parakeet v3/Unified, Silero VAD, and pyannote diarization as CoreML/ANE bundles. Its APIs were read from the checkout under `build/SourcePackages/`.
- **Summarization**: two switchable provider kinds — the Anthropic API (`claude-sonnet-5`, key in Keychain) *and* a headless CLI (Claude Code, Gemini CLI, Codex CLI). Both mandatory. Ollama remains a someday privacy fallback (16 GB of unified memory ⇒ ≤ 8B models; expect quality loss on 15k-token transcripts).
- **Storage**: SQLite (WAL) is the source of truth, Markdown the projection; search justified this split.
- **iOS**: not pursued; no iOS abstractions in the codebase.
